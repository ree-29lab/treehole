# 树洞

一个跑在自己电脑上的匿名留言板：任何人留下的内容都能被任何人回应，没有账号、没有昵称、没有访问统计。
用 Node 内置模块写成，**零运行时依赖**，不需要构建步骤，数据是一个 SQLite 文件。

- 访客：打开固定入口页 → 自动跳到当前隧道地址 → 输入一次口令 → 之后 30 天免输。
- 发内容：每条帖子自动分配一个代号（如「雾里的核桃·41」），同一条帖子里的发言共用同一个代号，跨帖子不通用。
- 回应：帖子下面可以回应，也可以回应某一条回应（两层）。
- 撤回：作者可以删掉自己发的内容，删除是**真的从数据库里消失**。
- 折叠：命中自伤类词的内容照常发布，但默认折叠并显示心理援助热线；命中联系方式 / 广告 / 开盒类词的内容会被拒收。
- 举报：任何人可举报，满 3 条自动折叠并进入后台待处理队列。

---

## 快速开始

```bash
bin/start.sh              # 起本机服务 + 公网隧道，并更新入口页
bin/start.sh --no-tunnel  # 只在本机跑
bin/stop.sh               # 全部停掉，并把入口页标记成没开门
```

首次运行会在 `data/secret.json` 里生成三个值：`secret`（签名密钥）、`passphrase`（访客口令）、
`adminPassphrase`（后台口令）。终端会打印口令和分享链接。

## 让别人也能打开

1. `bin/setup-pages.sh`（只需一次）——建 GitHub 仓库、推代码、开启 GitHub Pages。
2. `bin/start.sh`——起隧道并把当前公网地址写进入口页的 `docs/now.json`。
3. 把终端打印的分享链接整条发给朋友：

   ```
   https://<你的用户名>.github.io/treehole/#核桃-星轨-41
   ```

   口令放在 URL 的 `#` 后面：它不会被发给任何服务器、不会进 GitHub 仓库、也不会写进访问日志，
   浏览器读到之后自动拼成 `?k=口令` 完成验证。

入口页地址固定不变；隧道地址每次重启都会变，入口页会自动跟过去——所以**让对方收藏入口页，而不是隧道地址**。

## 常用改动

| 想改什么 | 改哪里 |
| --- | --- |
| 访客口令 / 后台口令 | `data/secret.json` 里的 `passphrase` / `adminPassphrase`（改完重启服务；旧 cookie 立即失效） |
| 关键词（折叠 / 拒收） | `config/keywords.json` |
| 心情标签 | `config/app.json` 的 `moods` |
| 频率限制、字数上限、举报阈值 | `config/app.json` 的 `limits`、`postMaxChars`、`reportHideThreshold` |
| 代号词表 | `config/words.json` |
| 预置内容 | `config/seed-posts.json`，然后 `node scripts/seed.mjs` |

## 管理与审核

后台在 `<当前公网地址>/admin`（进站后把地址栏域名后面加上 `/admin`），用管理员口令登录。可以：

- 看所有待处理举报，折叠 / 忽略 / 删除对应内容；
- 看已被折叠的内容并恢复；
- `GET /admin/export` 导出全部帖子、回应、举报为 JSON。

## 数据与隐私

- 全部数据在 `data/treehole.db`（SQLite，WAL 模式）。
- 数据库里**不存原设备 ID、不存原始 IP**：两者都只保存 HMAC 摘要。IP 摘要仅用于限流，7 天内自动清理。
- 页面不显示精确时间（只显示「3 小时前」这类相对时间）、不做搜索、不引任何第三方脚本或 CDN。
- 备份：`node scripts/backup.mjs` 会写出 `data/backup-YYYY-MM-DD.db`，只保留最近 7 份。
  想每天自动跑，可以挂一个 launchd / cron。
- 想彻底清空：停服务后删掉 `data/treehole.db*` 即可。

```

```

## 设计取舍

- **不用框架、不用 npm 依赖**：`node:http` + `node:sqlite` 够用，没有构建步骤，没有供应链风险，
  改一行刷新即可生效。
- **服务端渲染 + 原生表单**：没有 JS 也能发帖和回应；JS 只用来做抱抱不刷新、字数提示、二次确认。
- **口令而不是账号**：熟人小圈子不需要账号体系；口令进 cookie，改口令即可把外人全部挡出去。
- **单次 nonce**：每个表单带一个一次性令牌，防跨站提交、防重复提交（第二次提交返回 409）。
- **文本一律转义**：不支持任何 HTML / Markdown，换行转 `<br>`。匿名站点最致命的事故是 XSS——
  一旦成立，访客的身份 cookie 就能被偷走，匿名性直接归零。

## 已知限制与风险

1. **Mac 关机、合盖或断网，外面就打不开。** 这是「跑在自己电脑上」的代价。要长期在线，
   得把同一套代码放到一台常开的服务器上（改 `config/app.json` 的 `host`/`port` 即可）。
2. **入口页是公开的**，任何人都可能摸到，安全性完全靠口令；口令不要发到公开群里。
3. **微信里打开可能弹「非微信官方网页」提示**，必要时让对方「在浏览器中打开」。
4. **匿名不等于安全**：文风、事件细节、发帖时间都可能让人猜出是谁。版规里已经写明不要发布可识别信息，
   但那是提醒，不是技术保证。
5. **合规提醒**：在中国大陆提供互联网信息服务需要 ICP 备案（托管在境外可避开备案环节），
   而《网络安全法》第 24 条要求信息发布类服务做真实身份认证——匿名留言板天然不符。
   实际执法主要针对有规模的平台，但一旦站内出现违法内容被举报，**站长是第一责任人**。
   部署前请自行评估这一点。
6. **没有通知推送**：没有账号体系就做不到「有人回你了」的提醒；作者只能在「我发过的」里看回应数。
